## 0. 阅读说明与范围边界（必读）

本文档描述**企业家居网站（企业官网系统 + 后台管理系统）** 的本次交付版本需求。以下为**明确的范围边界**，所有未列入本次范围的功能均归入"后续迭代"（见第 11 章），不在本期开发与 PRD 细化范围内。

**本期明确不包含（仅占位/静态，后台无维护能力）：**
- 「新案例展示」前台页：使用写死的静态数据，后台不提供维护能力。
- 「招聘入口（社会招聘 / 校园招聘）」前台页：静态跳转页，仅展示静态文案，后台不维护职位、不接收简历投递。
- 产品详情页：**不展示价格**。
- 前台：纯展示型，无 C 端用户注册 / 登录。

> 注：原「关于TP」占位页已于 v1.2 纳入本期维护（更名为「关于栖木家具」，后台可维护），不再列入「不包含」范围，详见 4.5。

## 1. 项目概述

### 1.1 项目背景
客户为家居（家具）品牌「栖木家具」，需建设对外展示的企业官网（前台）与对内运营的内容管理后台（后台）。参考标杆站点为蓝鸟家居官网（https://www.lanniao.cn/，仅作结构与视觉参考，非最终品牌），定位为"品牌实力展示 + 产品/案例曝光 + 新闻资讯 + 招商/招聘入口"的综合性企业官网。

### 1.2 项目目标
- 对外：建设专业、可信赖的企业家居官网，承载品牌介绍、产品展示、新闻动态、联系转化（留言/询价）。
- 对内：提供易用的后台管理系统，支持多角色协同维护官网内容，保障内容发布的规范与安全。

### 1.2.1 可量化业务目标（建议基线，待业务方确认）
- 官网有效线索（留言/询价）月均 ≥ 50 条（上线首月基线为 0，3 个月内达成）。
- 产品中心可检索 SKU ≥ 50；内容发布平均耗时从"人工改代码"降至 < 10 分钟/条。
- 前台首屏加载 < 2s，移动端适配覆盖率 100%。

### 1.3 目标用户
- **前台访客**：潜在经销商、采购方、求职者、普通消费者、媒体。
- **后台用户（员工）**：超级管理员、内容编辑、客服/运营人员，通过 RBAC 分配权限。

### 1.4 产品定位
- 前台：纯展示型官网，仅中文，响应式适配 PC 与移动端。
- 后台：基于角色权限的内容运营管理平台。

### 1.5 技术栈
| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Python + FastAPI | RESTful API，SQLAlchemy ORM |
| 数据库 | SQLite | 轻量关系型，单文件部署 |
| 前端（前台） | React + Tailwind CSS | 企业官网展示 |
| 前端（后台） | React + Ant Design | 管理后台 |
| 鉴权 | JWT | 后台登录与接口鉴权 |

### 1.6 核心用户故事（Why 优先）
> 需求动机以用户故事承载，作为功能取舍与优先级判据。

- 作为**潜在经销商**，我希望在官网查看各系列/空间的家具产品与规格，以便评估是否代理合作。
- 作为**采购方/消费者**，我希望通过留言/询价表单快速联系品牌方，以便获取报价与方案。
- 作为**内容编辑**，我希望在后台可视化维护产品与新闻，以便无需开发介入即可更新官网。
- 作为**客服/运营**，我希望在后台集中查看并处理留言，以便及时跟进线索、提升转化。
- 作为**超级管理员**，我希望通过角色权限管控团队成员的后台操作范围，以便保障内容与系统安全。

## 2. 用户角色与权限（RBAC）

### 2.1 角色定义
| 角色编码 | 角色名称 | 职责说明 |
|---|---|---|
| `super_admin` | 超级管理员 | 拥有全部权限，负责用户/角色管理、系统配置 |
| `content_editor` | 内容编辑 | 维护产品、新闻资讯、轮播图、企业资料等内容 |
| `operator` | 客服/运营 | 查看并处理前台留言/询价，查看仪表盘 |

> 说明：角色与权限通过后台「用户与角色权限管理」模块配置，支持后续扩展新角色。

### 2.2 权限模型
采用「资源:操作」权限编码，权限经角色聚合后授予用户。操作类型：`view`（查看）、`create`（新增）、`edit`（编辑）、`delete`（删除）、`manage`（管理，含上述全部）。

### 2.3 权限矩阵
| 权限编码 | 说明 | 超级管理员 | 内容编辑 | 客服/运营 |
|---|---|:---:|:---:|:---:|
| `dashboard:view` | 仪表盘查看 | ✓ | ✓ | ✓ |
| `product:view` | 产品查看 | ✓ | ✓ | — |
| `product:create` | 产品新增 | ✓ | ✓ | — |
| `product:edit` | 产品编辑 | ✓ | ✓ | — |
| `product:delete` | 产品删除 | ✓ | ✓ | — |
| `news:view` | 新闻查看 | ✓ | ✓ | — |
| `news:create` | 新闻新增 | ✓ | ✓ | — |
| `news:edit` | 新闻编辑 | ✓ | ✓ | — |
| `news:delete` | 新闻删除 | ✓ | ✓ | — |
| `banner:manage` | 轮播图管理 | ✓ | ✓ | — |
| `about:manage` | 企业资料管理 | ✓ | ✓ | — |
| `message:view` | 留言/询价查看 | ✓ | — | ✓ |
| `message:handle` | 留言/询价处理 | ✓ | — | ✓ |
| `rbac:user:manage` | 用户管理 | ✓ | — | — |
| `rbac:role:manage` | 角色与权限管理 | ✓ | — | — |

> 注：`about:manage` 覆盖发展历程 / 品牌介绍 / 联系我们 / **关于栖木家具**（v1.2 起纳入维护，不再为占位页）。

**v1.2 变更（权限配置界面）**：后台「角色与权限管理」已移除逐权限勾选矩阵 UI；角色权限改为**预设分配**（创建/编辑角色仅维护名称与描述，权限按预设角色模板赋予，不支持单权限勾选）。上表权限矩阵仍为系统权限基线定义。

## 4. 前台功能需求（纯展示型）

> 所有前台数据均来自后端 API（除明确标注"静态"的模块外）。前台仅做展示与表单提交，无 C 端账户体系。

### 4.1 首页
- **轮播 Banner**：展示后台配置的轮播图（图片 + 标题 + 跳转链接）。
- **品牌实力区**：企业简介摘要、关键数据（成立年份、厂区面积、生产线等，来自企业资料）。
- **产品系列入口**：展示产品系列（如胡桃禮/如意春等）卡片，点击进入产品中心。
- **新闻动态**：最新企业新闻/行业资讯列表（取最近 N 条）。
- **招聘/招商入口**：跳转至招聘入口页/联系我们页的引导位。
- **页脚**：公司名称、联系方式、社交账号、备案信息（来自站点配置）。

### 4.2 产品
#### 4.2.1 产品中心
- 筛选：按**系列**与**适用空间（分类）**组合筛选；支持关键词搜索。
- 列表：分页展示产品卡片（封面图、名称、系列、适用空间）。
- 排序：支持按后台设置的排序字段展示。
- 详情页（`/products/:id`）：
  - 展示字段：**产品名称、系列、适用空间、材质、尺寸、风格、图文详情**。
  - **不展示价格**。
  - 图片画廊（封面 + 多图）。
  - 相关产品推荐（同系列/同空间）：**本期不做**，留待后续迭代。
  - 「留言/询价」快捷入口（带入产品信息提交）。

#### 4.2.2 新案例展示（静态）
- **本期为写死静态数据**，展示若干案例图文（图片 + 标题 + 简介）。
- 后台不提供维护能力；数据以后端静态配置/前端内置方式维护。

### 4.3 新闻
- **企业新闻**与**行业资讯**两个二级栏目，分别对应新闻分类。
- 列表：分页、按发布时间倒序，展示标题、封面、摘要、日期。
- 详情页：正文、发布时间；**阅读量统计本期不做**（字段预留，见 6.3）。

### 4.4 招聘入口（静态）
- **社会招聘 / 校园招聘**为静态跳转页，**仅展示静态招聘文案**。
- 本期后台不维护职位，不接收简历投递。

### 4.5 关于我们
- **关于栖木家具**：本期填充真实企业介绍内容（成立时间、总部、理念、制造实力等），后台 `about:manage` 提供「关于栖木家具」富文本维护入口。
- **发展历程**：时间轴形式展示里程碑（来自企业资料模块）。
- **品牌介绍**：品牌理念、实力、荣誉等内容（来自企业资料模块）。
- **联系我们**：
  - 展示公司地址、电话、邮箱、地图（来自站点配置/企业资料）。
  - **留言/询价表单**：字段含 姓名、电话、邮箱（选填）、类型（留言/询价）、关联产品（选填）、内容；提交后进入后台「留言/询价管理」。

## 5. 后台功能需求（Ant Design）

### 5.1 登录与鉴权
- 登录页：用户名 + 密码，JWT 鉴权；登录失败次数限制（如 5 次/10 分钟锁定，安全需求，必须实现）。
- 登录后进入仪表盘；未登录访问受保护路由自动跳转登录页。
- 权限中间件：接口级 RBAC 校验，越权返回 403。

### 5.2 仪表盘
- 概览卡片：产品总数、新闻总数、待处理留言数、Banner 数量。
- 待办提醒：未处理留言/询价列表快捷入口。

### 5.3 产品管理
- **分类管理（适用空间）**：新增/编辑/删除/排序，如 卧室、客厅、餐厅、书房、茶室、办公。
- **系列管理**：新增/编辑/删除/排序，如 胡桃禮、如意春、禧YUE、柏悦、蓝宝嘉、办公家具、软体。
- **产品 CRUD**：
  - 字段：名称、编号、所属系列、适用空间（分类）、材质、尺寸、风格、图文详情、封面图、多图画廊、排序、状态（上/下线）。
  - 图片上传：支持本地/对象存储上传，限制格式与大小。
  - 列表：分页、筛选（系列/分类/状态）、搜索、排序调整。

### 5.4 新闻/资讯管理
- **分类**：企业新闻、行业资讯（可配置）。
- **CRUD**：标题、分类、封面图、摘要、正文（富文本）、作者、状态（草稿/发布）、发布时间。
- 列表：分页、筛选、搜索；支持置顶/排序。

### 5.5 轮播图 / Banner 管理
- CRUD：标题、图片、跳转链接（站内/外链）、排序、状态、展示时间窗（开始/结束，可选）。
- 列表管理，支持启停与排序。

### 5.6 企业资料 / 关于我们内容管理
- **发展历程**：时间轴条目管理（年份、标题、描述、图片）。
- **品牌介绍**：富文本/分块内容维护。
- **联系我们**：公司名称、地址、电话、邮箱、地图嵌入信息、社交账号等，统一维护。
- **关于栖木家具**：本期**提供维护入口**（`about:manage` 含「关于栖木家具」富文本），与品牌介绍/发展历程/联系我们一同维护。

### 5.7 留言/询价管理
- 列表：来自前台表单提交，分页、按类型/状态筛选、搜索。
- 字段：姓名、电话、邮箱、类型（留言/询价）、关联产品、内容、提交时间、状态（未处理/已处理）、处理回复、处理人、处理时间。
- 操作：查看详情、标记处理、填写回复（回复可仅后台记录，或可选邮件通知，本期不强制）。

### 5.8 用户与角色权限管理（RBAC）
- **用户管理**：新增/编辑/停用用户，分配角色；密码重置。
- **角色管理**：新增/编辑角色（名称/描述），权限按预设模板分配（v1.2 起不再提供逐权限勾选矩阵 UI）；删除角色（存在用户时限制，超级管理员不可删）。
- **权限基线**：权限编码见 2.3 矩阵，作为系统权限定义；后台界面不再以模块+操作树状勾选展示。
- 超级管理员角色默认不可被删除/降权。

## 6. 数据模型（库表设计，文字表格）

> 使用 SQLite。布尔以 INTEGER(0/1) 存储；时间统一 UTC 或本地时间并注明；图片以 URL 字符串存储。

### 6.1 账户与权限
**users（用户）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| username | TEXT UNIQUE | 登录名 |
| password_hash | TEXT | bcrypt 哈希 |
| real_name | TEXT | 姓名 |
| email | TEXT | 邮箱 |
| phone | TEXT | 电话 |
| role_id | INTEGER FK | 关联 roles |
| status | INTEGER | 1启用/0停用 |
| last_login_at | DATETIME | 最近登录 |
| created_at | DATETIME | 创建时间 |

**roles（角色）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT | 角色名 |
| code | TEXT UNIQUE | 角色编码 |
| description | TEXT | 描述 |
| created_at | DATETIME | 创建时间 |

**permissions（权限）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT | 权限名 |
| code | TEXT UNIQUE | 如 product:edit |
| module | TEXT | 所属模块 |

**role_permissions（角色-权限）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| role_id | INTEGER FK | 角色 |
| permission_id | INTEGER FK | 权限 |

| parent_id | INTEGER | 预留父级（本期可空） |
| sort | INTEGER | 排序 |
| status | INTEGER | 1启用/0停用 |

**product_series（产品系列）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT | 系列名 |
| sort | INTEGER | 排序 |
| status | INTEGER | 状态 |

**products（产品）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| name | TEXT | 名称 |
| code | TEXT | 编号 |
| series_id | INTEGER FK | 系列 |
| category_id | INTEGER FK | 适用空间 |
| material | TEXT | 材质 |
| size | TEXT | 尺寸 |
| style | TEXT | 风格 |

| cover_image | TEXT | 封面URL |
| gallery | TEXT | 多图URL（JSON数组） |
| sort | INTEGER | 排序 |

### 6.3 新闻
**news_categories（新闻分类）**

**news（新闻）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| title | TEXT | 标题 |
| category_id | INTEGER FK | 分类 |
| cover_image | TEXT | 封面 |
| summary | TEXT | 摘要 |
| content | TEXT | 正文（富文本） |
| author | TEXT | 作者 |

### 7.8 通用约定（响应格式 / 分页 / 错误码）
- **统一响应**：
  - 成功：`{ "code": 0, "message": "ok", "data": ... }`
  - 失败：`{ "code": <业务码>, "message": "<错误信息>", "data": null }`
- **分页参数**：列表接口统一 `?page=1&page_size=20`；响应 `data` 含 `{ "items": [...], "total": N, "page": 1, "page_size": 20 }`。
- **错误码**：401 未认证 / 403 无权限 / 422 参数校验失败 / 429 限流 / 5xx 服务端；业务码在 10000+ 段自定义。
- **鉴权失败**：缺失/过期 Token 返回 401，前端跳转登录。

### 7.9 文件上传
| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/v1/admin/upload` | 上传图片，返回可访问 URL（支持产品图、新闻封面、Banner 等） | 需登录（按资源归属再行 RBAC 校验） |

- **存储**：本期采用本地 `uploads/` 目录 + 静态服务（或反向代理映射）；URL 持久化到对应表字段。
- **限制**：格式 `jpg/png/webp`，单文件 ≤ 2MB，服务端重命名防覆盖；后续可平滑切换对象存储。

## 8. 非功能性需求

| 类别 | 要求 |
|---|---|
| 性能 | 前台首屏 < 2s；列表接口响应 < 500ms（常规数据量）；列表分页，单页 ≤ 20 条 |
| 安全 | JWT 鉴权；密码 bcrypt 哈希；接口 RBAC 校验；输入校验与参数化查询防注入；富文本 XSS 过滤；文件上传类型/大小限制；登录失败限流 |
| 兼容性 | 前台响应式（PC + 移动端）；后台以桌面端为主；支持主流现代浏览器（Chrome/Edge/Firefox/Safari 近两版本） |
| SEO | 关键页面 meta 标题/描述；语义化结构；可选 sitemap |
| 可维护性 | 后端分层（router/service/repository）；API 版本化（/api/v1）；前后端分离；统一响应与错误码 |
| 数据 | SQLite 单文件；定期备份机制（运维侧） |
| 部署 | 后端 uvicorn/gunicorn；前端静态构建；本期无强容器化要求 |

### 8.1 个人信息合规（PIPL）
留言/询价模块收集手机号、邮箱等个人信息，须满足《个人信息保护法》要求：
- **告知同意**：表单须明示收集目的、范围，提交即视为同意；隐私政策可访问。
- **最小必要**：仅收集处理所需字段（姓名、电话为必填，邮箱选填）。
- **存储与保留**：个人信息加密存储；设定保留期限（建议 ≤ 24 个月）到期清理或匿名化。
- **访问控制**：仅授权客服/运营角色可查看；列表/详情对手机号做脱敏展示（如 138****8000）。
- **不共享**：本期不向第三方共享/出售个人信息。

| 健康 | 后台接口可用率 | ≥ 99.5% |
| 健康 | 待处理留言 24h 处理率 | ≥ 90% |

### 9.2 验收标准（Definition of Done）
- **前台**：5 主导航 + 二级栏目全部可访问；产品可按系列/空间筛选并查看详情（含材质/尺寸/风格/适用空间，无价格）；新闻列表与详情可用；留言表单提交后能在后台查到；静态案例/招聘按约定呈现；关于栖木家具页展示真实内容且后台可维护。
- **后台**：三类角色可按预设权限登录并操作（角色权限为预设，后台无逐权限勾选配置）；产品/新闻/Banner/企业资料 CRUD 生效并即时反映到前台；留言可处理并标记；越权接口返回 403。
- **质量**：统一响应与错误码落地；图片上传可用；个人信息脱敏与合规项满足；移动端响应式通过。

### 9.3 风险与依赖
- **内容依赖**：前台效果依赖业务方提供产品/新闻/企业资料素材，建议阶段 1 即启动素材收集。
- **合规风险**：留言涉及个人信息，上线前需隐私政策与告知同意落地，否则存在合规风险。
- **静态模块**：案例/招聘本期静态，后续迭代需评估改为后台维护的改造量。
- **性能依赖**：SQLite 在高频写入/高并发场景存在上限，若预估流量超预期需评估迁移 PostgreSQL。
